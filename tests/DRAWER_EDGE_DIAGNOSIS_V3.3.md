# V3.3 抽屉白边：定位证据与修复验收

## 结论

白色弧边是抽屉没有完全移出视口后露出的右沿，不是页面动画残影。
抽屉右侧常驻阴影进一步形成了首页左侧的灰色阴影带。
这一问题可直接在原始 V3.2 单文件中复现，不依赖 ChatGPT 预览器、动画暂停或缓存。

## 排查顺序

先读取并运行原始 V3.2，完成真实演示登录；测量抽屉与主页面坐标；再用浏览器临时样式逐层隔离。确认根因后才在独立 V3.3 副本中修复。V3.2 单文件未被覆盖。

### 两套宽度不一致

V3.2 的 `styles.css` 第 992—994 行使用：

```css
.drawer {
  width: min(88%, 388px);
  border-radius: 0 27px 27px 0;
  box-shadow: 22px 0 56px rgba(36,47,32,.18);
}
```

但 `app.js` 第 1175—1180 行关闭抽屉时仍按旧宽度移动：

```js
function drawerWidth() {
  return Math.min(frame.clientWidth * .86, 380);
}
drawerEl.style.transform = `translate3d(${(-1+p)*w}px,0,0)`;
```

390px 视口实测：实际抽屉宽 343.1875px；关闭时只左移 335.4000px；抽屉右边缘仍在视口内 x=7.7875px。主页面自身 x=0，并没有偏移。
517px 视口时，两边分别被 388px 和 380px 上限限制，仍漏出 8px。

### 图层隔离结果

| 操作 | 白色抽屉边 | 左侧灰影 | 结论 |
|---|---|---|---|
| 原始 V3.2、抽屉从未打开 | 存在 | 存在 | 非关闭动画残影 |
| 仅临时取消抽屉阴影 | 仍存在 | 消失 | 白条是抽屉实体 |
| 仅临时隐藏整个抽屉 | 消失 | 消失 | 来源锁定抽屉 |
| 只改为按自身宽度移出 | 消失 | 仍存在 | 仅修宽度不够 |
| 自身宽度移出，同时关闭阴影 | 消失 | 消失 | 两项都要处理 |

原始截图与浏览器临时隔离截图保存在 `tests/diagnosis-v32/`；这些不是设计效果图。

### 额外发现：视口变化

原实现把关闭位置写成固定像素。390px 视口关闭后直接扩大到 768px，若尚未重新开关抽屉，抽屉右边缘可进入视口 52.6px。原因仍是实际宽度与旧像素位移脱节。

## 为什么 V3.1 / V3.2 的测试漏掉

之前的无边缘测试只检查 App Frame、Main、Screen 的 x、宽度、transform 和横向滚动，没有检查关闭抽屉的右边界、阴影、可见性及命中区域。
“主页面 x=0”和“没有横向滚动”都不能证明上层抽屉没有覆盖主页面。历史报告将转场视为此次根因的结论应撤回。

## V3.3 最小修复范围

1. 抽屉宽度只由 CSS 定义一份，保留 V3 的 `min(88%,388px)` 设计尺寸。
2. 关闭位移改为 `translate3d(-100%,0,0)`，相对抽屉自身宽度；拖动阈值读取实际尺寸，不再维护另一份比例/上限。
3. 完全关闭后设置 `visibility:hidden`、`pointer-events:none`、`inert`，并取消抽屉阴影。
4. 遮罩在关闭完成后隐藏，主页面变换和圆角恢复零值；立即进入二级页面时不残留默认圆角过渡。
5. 打开、拖动、关闭中继续保留原有抽屉造型和动画；处理 transitionend、快速反向操作、待执行 RAF 与 pointercancel，防止关完后被旧回调重画。
6. 没有调整首页布局、图标、文案、登录规则、正面解读状态机、测评或原返回路由逻辑。
